## Runbook notes (two likely failure modes of the agents)
1. **Runs end as specialist-review with "Research did not finish".** Confirm: `limits_used` in the result and a `limit` / `stopped` event in the trace (`docker compose logs agent-worker | grep <run_id>`). Recover: check retrieval health and latency first (a slow or empty index burns steps); raise `AGENT_MAX_STEPS` or `AGENT_MAX_WALL_S` only if retrieval is healthy and runs are simply long.
2. **Many runs end as specialist-review with `degraded: true`.** Confirm: `summary_unavailable` events in the trace and the provider or stub status (`docker compose ps stub-llm`, `curl localhost:8001/health` if exposed). Recover: restart the model service or fix the key or quota; the findings are still correct (deterministic), only the model summary is missing.
